# Где что находится

1. На GitHub открой папку **src** и нажми на нужный файл — увидишь его код.
2. **MergeSorter.java** и **QuickSorter.java** — две сортировки.
3. **DeterministicSelector.java** — поиск k-го наименьшего числа. k считается с нуля.
4. **ClosestPairSolver.java** — поиск минимального расстояния между точками.
5. **Main.java** — небольшой пример запуска всех четырёх алгоритмов. Массив `input` можно менять.

## Как запустить

Скачай проект: GitHub → Code → Download ZIP. Распакуй его. В IntelliJ IDEA выбери Open и открой папку с pom.xml как Maven-проект. Выбери JDK 17.

- Открой Main.java → зелёная кнопка около main → Run: увидишь примеры внизу окна.
- Открой tests/AlgorithmTests.java → Run: запустятся проверки.
- Открой Experiment.java → Run: обновятся CSV в results.
- Открой PlotResults.java → Run: по CSV построятся графики в docs/plots.

Рабочая папка запуска (Working directory) должна быть папкой с pom.xml. Python и Shell для проекта не нужны. pom.xml — настройки Java-проекта, CSV — таблицы результатов, PNG — картинки, Markdown — текст отчёта.

В задании просят не только сортировки: ещё нужны выбор k-го числа и ближайшая пара точек. Также обязательны тесты, замеры, графики, скриншоты, README и история Git. Поэтому эти части сохранены.

## Откуда берутся графики

Experiment.java создаёт массив или точки и 5 раз запускает алгоритм для прогрева Java. Затем делает 7 замеров: время после запуска минус время до запуска. Для этого используется System.nanoTime(). Создание входных данных в замер не входит.

Семь времён сортируются. Берётся четвёртое, среднее по положению число — медиана, а не среднее арифметическое. Наносекунды делятся на 1 000 000, чтобы получить миллисекунды. Например, 6 114 416 нс = 6,114416 мс.

Metrics.java считает глубину: сколько вызовов алгоритма одновременно открыто. Начальный вызов имеет глубину 1, вложенный — 2 и так далее. Для графика берётся наибольшая глубина за 7 запусков. Это не количество всех вызовов за всё время.

Результаты записываются в results/results.csv. PlotResults.java читает числа из этой таблицы и рисует точки. Цвет обозначает алгоритм, горизонтальная ось — размер входа. В первом графике вертикальная ось — время, во втором — глубина. Четыре панели соответствуют четырём типам данных.

По горизонтали каждый шаг увеличивает размер в 10 раз: 100 → 1 000 → 10 000 → 100 000. На графике времени вертикальные шаги тоже отличаются в 10 раз. Поэтому он не похож на график с обычной линейной шкалой. Соединительные линии помогают видеть изменения; между четырьмя размерами замеры не проводились.

Чтобы воспроизвести: запусти Experiment.main(), затем PlotResults.main(). Время на твоём компьютере может отличаться. Если меняешь результаты, нужно также обновить числа в таблицах README и скриншоты.

## Чем отличаются четыре алгоритма

- MergeSort делит числа пополам, сортирует половины и сливает их. Пример: [3, 1] и [4, 2] становятся [1, 3] и [2, 4], затем [1, 2, 3, 4].
- QuickSort выбирает опорное число. Для [3, 1, 4, 2] с опорным 3 получаются меньшие [1, 2], равные [3] и большие [4]. Затем обрабатываются меньшая и большая группы.
- Median-of-Medians ищет только число на нужной позиции. Для того же массива k=1 означает второе наименьшее, то есть 2. Полностью сортировать массив для ответа не нужно.
- Closest Pair работает с точками, а не с сортировкой чисел. Ответ — расстояние между двумя самыми близкими точками.

Сравнивать время MergeSort и QuickSort можно как два способа решить одну задачу. Выбор одного числа и поиск расстояния решают другие задачи: меньшая цифра времени не делает их заменой сортировке.
